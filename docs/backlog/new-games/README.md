## Как это делалось

Скрипты Workflow — в `workflows/` рядом (пути в args — локальные, поменять под себя).
`moood-me/moood:docs/writing/stage1-protocol.md` — более ранняя запись того же порядка кругов (с лимитом 10 и старыми
промптами); действующее — скрипт ниже, лимит кругов задаёт Павел.

### Стадия 1 — `workflows/scenarios-reduce.js`

- Автор — один Opus на сценарий; он отвечает за готовность сам («не полагайся на ревьюеров как на страховку»),
  без инструкций о методе. Помнит замечания всех прошлых кругов (они идут ему по порядку).
- Ревью — четыре свежих независимых Opus (А, Б, В, Г) на круг. Ревьюеры видят **только сценарий и документы**: ни
  ответов автора, ни истории правок. Поэтому в файле сценария нет разделов «Ответы на ревью».
- Схема «reduce»: полный круг из четырёх → автор правит → перепроверяют только сказавшие «нет» → когда все они
  «хорошо» — полный контрольный круг из четырёх. Прошёл — когда все четыре «хорошо» в одном круге.
- `max` — сколько кругов ревью (Павел задаёт: обычно 5). `fresh: true` — написать с нуля; `startReviews` +
  `startGroups` — продолжить: автор сначала правит по прошлым замечаниям, потом перепроверяют `startGroups`.
- `timeless: true` + `images` — мир вне времени и страны в духе сцен, которые нравятся Павлу: картинки в `look/`.
- После прогона: история ревью прошедших → `reviews.md`, коммит и пуш в `five-scenarios`.

Почему пятеро не сходятся (разбор): автор правит хорошо (серьёзных 9 → 6 → 2 → 1), но свежие ревьюеры каждый раз
пробуют другие ветки и находят то, что было в тексте с самого начала. Замечания идут семьями (в «Летней книге» —
Папа, в «Орфее» — «закон воды», в «Невидимых городах» — «цена не видна»). Бывает, что правка вызывает новое
замечание: Б/В требуют «цена должна быть видна», автор заставляет героя сказать её вслух, Г ловит это как гладкость.

### Стадия 2 — `workflows/stage2-owned.js`

Один Opus-сценограф на мир: создаёт мир на деве (если его нет; в облачной сессии мир создаёт координатор — `create_world`, потом `add_repo` для `moood-me/pavel--<мир>` и клон; сценографу — `world`, `empty: true`, `clone`: git там без токена), делает первую сцену, потом ещё 1–2. Он сам смотрит
выборочные рендеры на GPU дева (`look_at_branch` с `on: "gpu"`), правит, пока сам не доволен, Sonnet зовёт только
если хочет. Материалы: MCP moood `guide`, `scene_format`, `people_guide`, образец — мир `pavel/scarlet-sails`.
Тексты мира по-английски, русский перевод — `node moood/packages/check/cli.js <клон> --write`, перевести, потом
без `--write` → «all right»; без переводов в `env/dev` не вливать.

## Как Павел работает (важное)

- Простой русский, полные фразы; без предложений «что дальше» в конце; критично, когда спрашивает.
- Вопрос и замечание — не приказ. Делать то, что сказано повелительно; если кажется, что нужно ещё что-то — спросить.
  Его «хочу / не хочу» — не повеление. Не суетиться: не перезапускать, не «чинить» без просьбы.
- Не микроменеджить агентов, не превращать его пожелания в жёсткие правила, здравый смысл важнее всего.
- Ревьюеры независимы, без подсказок и читов.
- Opus — для письма, кода сцен и ревью; Sonnet — для простого.
- Слова: процесс — «стадии написания игр»; о сценах не говорить «фильм».
- Git: коммит и пуш на каждом шаге; в main и dev — только с разрешения.
- Секреты — никогда в чат, URL, файлы и логи; токен world_repo — только в заголовке.
- Рендер — на GPU дева (HF), не локально.
