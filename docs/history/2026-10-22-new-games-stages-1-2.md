# Новые игры: стадия 1 и стадия 2 по 16 мирам

2026-10-20 — 2026-10-22, локальная сессия. Первые новые игры по «стадиям написания игр» (`docs/writing-games-v2/`):
сценарии 22 источников через стадию 1, миры для 16 прошедших через стадию 2. Где что лежит и как подхватить —
`docs/backlog/new-games/README.md`; скрипты Workflow — там же, `workflows/`.

## Стадия 1 — `scenarios-reduce.js`

- Автор — один Opus на сценарий, отвечает за готовность сам, без инструкций о методе. Между кругами автор каждый
  раз новый, но получает замечания всех прошлых кругов по порядку (память в промпте, `past` в скрипте; для
  продолжения — `startReviews`: файл с историей).
- Ревью — четыре свежих независимых Opus (группы А, Б, В, Г, `scenario-reviews.md`), structured output: verdict,
  summary, checked, blockers, serious, minor. Ревьюеры видят только сценарий и документы. Поэтому из сценариев
  удалены разделы «Ответы на ревью», и автору не говорят писать ответы в файл.
- Схема reduce: полный круг → правка → только сказавшие «нет» → когда они «хорошо», полный контрольный круг.
  Прошёл — все четыре «хорошо», без блокеров и серьёзного, в одном круге. `max` — сколько кругов ревью (Павел
  ставил 5, для «Неизвестного острова» 8). Если суженный круг прошёл на последнем круге, контрольный добирается
  отдельно: `startGroups` без `startReviews` — один круг оставшихся групп, без правки (так прошли «Невидимые города»).
- Не все ревьюеры ответили (сеть, API) — круг повторяется; при обрыве сети это крутится до её возвращения, а прогон
  может умереть без уведомления — тогда `resumeFromRunId`, пройденные круги берутся из кэша.
- `reviews.md` прошедших собирается из `result` прогона: круги по порядку, у ревьюера вердикт, сводка, проверенное,
  блокеры, серьёзное, мелкое; между кругами — ответ автора.

Итог по 22: прошли 16; не сошлись «Волшебник Земноморья» (5 кругов, один дополнительный и ещё 5) и «Неизвестный
остров» (5 и ещё 8);
остановлены без доводки «Станционный смотритель», «Утиная охота», own-1 «Ведущий», own-2 «Снятие».

Почему не сходится: автор правит хорошо (серьёзных 9 → 6 → 2 → 1), но свежие ревьюеры каждый раз идут по другим
веткам и находят то, что было в тексте с начала. Замечания идут семьями по одному месту сценария. Бывает, что правка
вызывает новое замечание: Б/В просят «цену видно», автор говорит её вслух устами героя, Г ловит гладкость. Помогли
память автора между кругами и больше кругов.

## Стадия 2 — `stage2-owned.js`

Один Opus-сценограф на мир: `create_world` на деве (`read_access: private`), сцена в git мира (ветка от `env/dev`,
`look_at_branch` с `on: "gpu"`, влить в `env/dev`), смотрит выборочные кадры сам, Sonnet — если сам захочет;
образец каста — `pavel/scarlet-sails`. Тексты по-английски, перевод — `moood/packages/check` (`--write`, потом
проверка → «all right»). `scenes` — сколько сцен (12 первых миров — по 2–3, 4 последних — по одной). Если мир уже
есть, агенту дают `world` и `done` — он доводит начатое.

Миры и id сцен — таблица в README. Общее у всех: люди кукольные, лица мелкие или простые; новых поз нет (Kimodo
на паузе); `measure_scene` у части сцен немного не проходит, в основном аллокации движка. В «Гордости» две параллельные
попытки разошлись в общем `modules/cast.js` — слиты одним агентом (тело Томсона из env/dev, лица и фрак из пятого
круга, голова 1.14).
